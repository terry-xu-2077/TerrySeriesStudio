# TerrySeriesStudio · 沉浸式共写 Demo

> 2026-10-27 · **独立静态前端原型**，不连接真实 AI API、ComfyUI、数据库或 Python。

这一版推翻了此前「Word 式批注 → 批量提交 AI 批改」的交互，改成更贴近「一边构思、一边和 AI 对话式共写」的沉浸式剧本编辑体验。

## 怎么打开

从仓库下载或克隆源码后，**双击 [index.html](index.html)** 即可使用。Chrome / Edge 均可；不需要 npm install、Node.js 服务、构建或 ComfyUI。

## 现在可以实际操作什么

1. **直接写**：页面中心就是剧本正文，点击即可编辑，自动保存。
2. **框选一段文字 → 跟 AI 聊这段**：选中任意文字会出现「💬 跟 AI 聊这段」按钮。点击后右侧共写面板会打开一个话题，顶部带着你选中的引用；在输入框里告诉 AI 想怎么改。
3. **AI 给出一版修改，由你决定要不要用**：AI 回复会展示「原文 → 改写后」的对比卡片，有两个按钮——**「✓ 采用」**直接把改写写回正文（正文会短暂高亮）；**「不满意，再改一版」**可以继续说明哪里不好（也可以留空直接要求换一种写法），AI 会在同一个话题里再给一版，旧版本保留但标记为「未采用」。
4. **不针对某一句，也能随便聊**：不选中任何文字，直接在输入框打字，AI 会以讨论的方式回复（人物动机、节奏、调性等），但不会改写正文——这类问题本来就不该由 AI 直接代笔。
5. **沉浸续写**：把光标停在正文最后一段的末尾，停顿约一秒，AI 会在下一行用灰色斜体给出续写建议，**按 Tab 采纳**，继续打字或按其他键则会消失。这个建议只在你正在写的最后一段末尾出现，不会打断你正在编辑的其它地方。
6. **左侧小圆点**：哪一段正文有共写记录，左侧会出现一个小圆点；高亮的点表示还有一版修改等你确认，点击可以直接跳到对应话题。
7. **批准本稿**：顶栏右侧的「批准本稿」是独立的定稿动作，和共写对话无关；如果还有待确认的修改，会先提示你。
8. **重置**：顶栏「⟲ 重置」清除浏览器里保存的 Demo 状态，恢复到初始示例。

## 为什么要推翻重写

此前的版本按 [docs/REVIEW_EDITOR.md](../docs/REVIEW_EDITOR.md) 做的是「通读全文 → 多处批注暂存 → 一次性提交批改 → 逐条接受/忽略」的审校模式，更像编辑一份已经写完的稿子。这一版改成了创作过程中的对话式共写：选中就能聊，聊完当场看到改写、当场决定要不要用，更贴近「边想边写、边和 AI 讨论」的真实状态。**这是交互方向上的调整，`docs/REVIEW_EDITOR.md` 里基于批量批注的正式方案尚未同步更新**，后续接正式 API 前需要先对齐。

## 模拟限制（务必注意）

- **AI 回复是前端写死的模板，不是真实模型**。针对选中文字的改写，会根据你输入里的关键词（比如「具体」「太啰嗦」「有画面感」「像人话」）套用几种预设的改写策略，再按重试次数换一种写法；没有关键词命中时会有一个通用的兜底改写，保证「再改一版」永远有新内容，但不代表真的理解了你的意见。
- **续写建议同理**：灰色续写从几句预设文本里按简单规则挑一句，不是生成式续写。
- **综合讨论**里的回复也是几条按关键词匹配的预设文本，命中不到时会直接说明这是前端模拟、没有接入模型。
- 正文改动使用稳定的原文匹配定位（接受修改前会重新核对原文是否还和生成改写时一致），避免在原文已经变化的情况下写错位置；匹配失败会提示「原文已变化」而不是静默改错地方。
- localStorage 仅用于演示保存，不能替代后续的本地 Markdown/JSON 工程文件。

## 这版不做什么

- 不再包含分镜、生成、资产库几个标签页——这一版只聚焦剧本的沉浸式共写体验；分镜复用同一套交互时再单独设计。
- 不实现多人协作、讨论串置顶/归档、消息编辑/撤回等完整聊天产品功能。
- 不接真实 API、不接 ComfyUI、不使用数据库。

## 下一步应该从哪里开始

先确认「框选引用 → 对话改写 → 采用/再来一版」这套交互本身是否顺手，再决定是否也要把 [docs/REVIEW_EDITOR.md](../docs/REVIEW_EDITOR.md) 和 [docs/PLAN.md](../docs/PLAN.md) 里偏「批量批注审校」的描述改成对话式共写；两者目前并不一致。之后再接正式 React 工作台、工程文件持久化、真实 API 和两份 review Skill。
