# TerrySeriesStudio · Word 式 AI 批注交互 Demo

> 2026-10-20 · **独立静态前端原型**，不连接真实 AI API、ComfyUI、数据库或 Python。

## 怎么打开

从仓库下载或克隆源码后，**双击 [index.html](index.html)** 就能使用。Chrome / Edge 均可；不需要 npm install、Node.js 服务、构建或 ComfyUI。若启用 GitHub Pages，可直接访问本仓库首页部署后的页面。

## 默认布局：专注写作

**默认以正文为中心**：项目侧栏收起，尚未有批改意见时右侧结果栏也可保持隐藏。顶部中央只有一组「剧本 / 分镜 / 生成」工作区切换，左侧不再复制这三个入口。右上角「展开项目导航」可以查看剧集，再点「专注写作」恢复，布局选择保存在浏览器中。

编辑工具栏只留一个轻量「审阅」入口，用于显示/收起**右侧常驻结果栏**；这个结果栏包含「AI 批改全文」、批改卡片和接受/忽略，并用柔和关系线指向正文中的精确引用。选中文字后只出现一个「添加批改」浮动按钮，点击后在文字附近弹出小输入框。定稿按钮独立位于**页面顶部**，不与批改操作混排。

## 现在可以实际操作什么

1. 在 **剧本** 页直接点击文本编辑；鼠标选中一句话，出现单个「添加批改」按钮，点击后在选区附近的小浮窗输入意见，提交后该意见进入右侧结果栏。
2. 点击工具栏「审阅」→ 右侧结果栏内「AI 批改全文」，约 0.75 秒后出现 3 条**本地模拟的**结构化批注，右侧卡片通过关系线对应到正文。它们不会覆盖原文。部分建议提供一段可替换文字，点击「接受」才应用；也可以「忽略」，人工批注可「标记已处理」。
3. 点击任意右侧批注，文档滚动到相应位置，高亮相关的原文引用；正文改变后若匹配失效或歧义，建议禁用自动接受。
4. 切换到 **分镜** 页，可编辑分镜文本，使用同样的批注机制。此页的 AI 批改模拟的是镜头连续性、镜头意图等问题。
5. **撤销、重做、自动保存、批准本稿** 可操作。刷新或关闭浏览器后再打开，编辑内容和批注通常会从该浏览器的 localStorage 恢复。
6. **资产库** 为暂时只读的概念抽屉，**生成** 页为流程占位；这两个模块都尚未接入真实数据。

可以用右上角 **「重置示例」** 清除该浏览器保存的演示状态，并恢复初稿。

## 示例与正式资料的区别

演示文本只为呈现 Word 式批注交互，不作为《异星边境》正式剧本或设定。资产卡里的姓名和图形只是占位标签，不代表真实人物形象或音色。所有 AI 评论都来自前端的固定示例数据，没有调用 API、运行任何模型，也不消耗 token。

**需要人工确认的批改**使用深灰色背景：候选修改文字及「接受修改／忽略」两个操作在同一块高对比区域中；采纳或忽略后转为淡色历史记录，不再保持强调。动作叫「AI 批改全文」，返回的卡片叫「AI 批改结果」。

## 设计约束

- **保持 Word 式操作**：文字是界面中心；仅输入批改时使用浮窗，已经返回的批改意见在右侧固定呈现且与正文相连。不新增审核看板。**批准本稿是顶栏独立操作，不属于批改工具。**
- **统一批注格式**：后续真实 AI API 使用 [Terry Review v1](../src/review/schema.ts)；当前模拟字段同样包含 block_id、quote、comment、可选 replacement、severity。
- **保留原文**：仅接受建议后修改相应文字。通过稳定块 ID 与精确、唯一的原文匹配定位；不做模糊匹配。
- **非生产级存储**：localStorage 仅用于展示保存交互，不能替代后续的本地 Markdown/JSON 工程文件。
- **精简开发**：本 Demo 不引入 npm、桌面壳、后端、API 凭据、上传管理或完整 Word 文档排版。

## 下一步应该从哪里开始

先评估「选区批注 → 右侧意见 → 接受/忽略」是否自然，再将已经确认的交互移到正式 React 工作台。完成工程文件持久化后接真实 API、两份 review Skill 和共享批注 Schema；**不要把当前的模拟 AI 按钮当作完成 API 集成**。
