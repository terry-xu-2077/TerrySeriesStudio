# 角色、场景与声音资产库设计

> 状态：产品设计 / 尚未实现 · 2026-10-20  
> 目标：作为 TerrySeriesStudio 中贯穿剧本、分镜和视频生成阶段的项目级资产模块  
> 参考：[MieNodes 资产库指南](https://github.com/MieMieeeee/ComfyUI-MieNodes/blob/main/docs/ASSET_LIBRARY_GUIDE.md)、[统一资产节点](https://github.com/MieMieeeee/ComfyUI-MieNodes/blob/main/nodes/assets/nodes.py)、[资产/分镜确定性组装计划](https://github.com/MieMieeeee/ComfyUI-MieNodes/blob/main/docs/PLAN_STORYBOARD_ASSET.md)

## 1. 设计定位

**资产是一份可被 AI 理解、由作者维护、可以在整季持续复用的角色或场景档案，而不是一个上传文件。**

TerrySeriesStudio 原生管理资产：不要求在 ComfyUI 里摆放 Save/Load 资产节点，也不让 ComfyUI 成为剧集资产的唯一真相来源。ComfyUI 只接收当前镜头实际选中的参考图片、音频和由文字设定编译出的提示词。

MieNodes 提供了重要参考：资产具备名字、描述、角色音色及参考媒体；资产包被加载、按照稳定顺序组合后交给生成器；自动描述能节省重复书写。我们参考其数据流与错误处理思想，**不直接复制代码**。其仓库为 GPL-3.0，未来若打算直接复用代码须先审查许可证及兼容性。

## 2. 两类核心资产

### 2.1 角色资产 Character

一张角色档案至少有：
- **身份**：稳定的 `character_id`、名称、别名、身份、备注、可检索标签。
- **图片**：一张主形象图与多张可选参考图；可标注正面、侧面、全身、表情、服装、特殊状态等。支持单张三视图作为一个参考图。
- **声音**：零到多段可试听样本；每段标记音色版本、语言、情绪/语速等；单独保存文字音色描述。**音频非必填**，不能因为没有录音就禁止角色参与剧本或无对白镜头。
- **文本**：外貌的稳定事实、声音特征、性格、背景、人物关系、说话习惯及固定行为约束；区分**角色身份描述**与**当集临时状态**（服装更换、受伤、携带道具），防止镜头内容反写角色基准。
- **可编辑的结构化字段与自由备注并存**；作者明确锁定的事实不能被 AI 自动覆盖。

**声音资产是参考素材，不等于 Studio 自带配音/TTS/声音克隆功能。** 只有所选 ComfyUI 工作流支持音频参考时才实际传递；不支持时只能作为剧本/分镜的语音指导文本，不能伪称模型已听到音频。音频素材应有合法使用权。

### 2.2 场景资产 Location / Set

一张场景档案至少有：
- **身份**：稳定的 `location_id`、名称、别名、区域与标签。
- **图片**：一张主视觉与可选的不同方向、机位、空间结构、昼夜/天气变体，保留每张图的标签。
- **文本**：空间布局、出入口和物件位置、材质、光照、氛围、地点历史及不可违反的固定设定。
- **可选环境音**：一段或多段环境声音参考与氛围描述；首版只作为可查看与可引用素材，不引入剪辑或混音。
- **区分固定地点与拍摄条件**：同一个基地场景可以在不同镜头中变为白天、夜晚或受损状态，不因此复制多个互不关联的地点身份。

此处的 **Scene Asset（场景资产）≠ Storyboard Scene（剧本场次）**：前者是可复用的地点，后者是某集某次事件；一个地点可以出现于多集多场。

道具、载具、服装等首版允许作为通用素材分类；仅当 EP01 试产验证确有需求时才升级为独立复杂档案。

## 3. 资产使用流程

### 剧本 AI

自动提取/选用相关人物与地点的**文字设定和固定约束**，构成剧集上下文。只把与当前创作相关的内容传给云端模型，不把完整图片和音频库默认上传。AI 若提及不存在或别名歧义的角色/地点，给出待确认引用，不自行创造资产记录。

### 分镜 AI

分镜中每条 Shot 以 ID 绑定角色和场景，自动继承对应外貌、声音、空间信息；生成结构化可编辑的景别、镜头动作与提示。角色/场景资产变更时，可以定位受影响镜头并提示关联版本差异，不覆盖已批准分镜。

### 视频生成 / ComfyUI

- 只为**当前 ClipPlan** 选择需要的参考媒体（例如角色全身图 + 场景夜景图），不是把整个角色档案的所有图片都送进 H3。
- Provider/Profile 声明图片/音频数量、格式、尺寸和模式的能力限制；例如 H3 当前支持的参考数量限制在 **H3 Profile** 中而不是写死于资产库。
- 用稳定的 **asset_id + revision + media_id** 组合出当次 `AssetBindingManifest`，其中明确 `image_slot/audio_slot`、实际媒体哈希及用途；生成提示词的 `<Picture N>` / `<Audio N>` 从**同一份 manifest** 编译，绝不分别推算顺序。
- 不匹配、缺文件、超出模型输入上限时给出明确提示；必须由用户重新选择或执行显式策略，不得自动丢失引用、悄悄缩减声音或把人物图误认为场景图。
- 节点执行前的本地预检和实际提交检查都应验证同一份 manifest；Job 保存不可变快照。
- 支持角色/场景整体替换主参考图，但老 Job、历史结果继续引用旧版本。替换后标出受影响且可选择重跑的镜头。

### AI 生成描述（可选）

可用云端多模态 API 对图片生成外貌/环境描述，或辅助整理声音描述；**先保存为 AI 建议草稿，用户明确采纳后才写入资产档案**。纯文本模型不能从未听过的音频准确推断音色，不能把“想象的声音”标成真实音频分析。

## 4. 首版界面

在项目侧栏提供一个共用的 **资产库** 入口，至少两个分类：**角色** / **场景**。

- **卡片总览**：封面缩略图、名称、简短描述、图片/音频数量、引用状态；搜索、过滤、导入。
- **角色详情**：左侧主视觉和参考图集，右侧人物文本设定，下方音频播放器和音色描述；支持添加、替换、重新指定主图、改名和版本查看。
- **场景详情**：参考视角图集、空间/光照设定与可选环境音。
- **绑定交互**：在分镜卡片或生成任务内选择角色/场景，自动显示可选媒体；可以覆盖某镜头的参考图而不修改项目级档案。
- 资产图像以**适应显示**为默认，支持完整查看和缩放，不强制裁剪；媒体使用小尺寸缩略图，不把原始图片全部加载进页面。
- 文字与图片、声音三类信息并列呈现；不把声音藏在普通文件附件里。

统一内部数据概念：

```text
CharacterAsset / LocationAsset
  id, name, revision, tags, descriptions, lockedFacts
  media[] -> mediaId, kind(image/audio), path, hash, role, tags, metadata
  primaryImageId
  character-only: voiceDescriptions, relationships
  location-only: spatialRules, ambience

Shot
  characterIds[], locationAssetId?, narrativeIntent, ...
ClipPlan
  shotId, selectedMediaIds[], contextLinks[], ...
GenerationJob (immutable)
  assetBindingManifestSnapshot, promptSnapshot, workflowProfileSnapshot, ...
```

首版不强制固定图片或音频上限。上限来自用户实际可选的目标视频 Profile（能力），而不是资产库容量。

## 5. 参考 MieNodes 的具体取舍

| MieNodes 机制 | TerrySeriesStudio 决策 |
| --- | --- |
| 角色图 + 外貌描述 + 声音样本 + 音色描述；场景图 + 描述 | **采用数据包思想**；角色支持多图/多音及更多剧集级文本信息 |
| Load Asset 的单根资产包线及按 kind 校验 | **采用语义**；Studio 内是类型化资产对象，ComfyUI 端输入用标准映射 |
| 角色在前、场景在后的固定参考槽位和 Audio 槽位 | **采用显式顺序 manifest**；提示词与工作流引用从一个来源生成 |
| 同名资产、缺图、错位等主动报错 | **采用严格校验**，错误直接指向资产 ID 与镜头 |
| Auto 描述对空白字段调用 LLM | **采纳“可辅助起草”**，但初稿必须用户确认才进入固定设定 |
| 插件目录内的 asset_library 文件夹 | **不采用此存储位置**；资产保存在 Studio 项目数据目录，ComfyUI 为执行端 |
| 依赖节点 Queue 来保存资产、节点 UI 的 Save/Load | **不采用**；Studio 原生资产编辑及提交即保存，不占用 GPU 生成队列 |

MieNodes 指南同时记录旧版多图/多音磁盘格式和新版简化 Save/Load 节点。参照当前 `SaveAssetV2` 实现，它在一次保存时传递一张图和至多一个音频，同时磁盘底层兼容多素材；**不要把底层可保存多素材误认为统一节点可在一次执行中编辑任意多张参考图**。

## 6. 里程碑与验收

**M0：资产库最小版本**：角色/场景新建、图片/音频导入、文本设定、文件存储、稳定 ID、缩略图和持久化。首次以《异星边境》现有角色资产导入验证。

**M1：剧本绑定**：正确提供角色与场景文本上下文给云端 API；角色姓名与别名绑定、设定锁定和版本引用能追溯。

**M2：分镜绑定**：分镜生成的角色、场景引用可检查、改名后稳定、缺失时给出明确提示。

**M3：生成绑定**：以一场戏中至少两名角色、一个场景为例，图片/声音使用同一份 manifest 映射进 ComfyUI，校验提示词槽位与实际参考材料一一对应；更换主参考图后旧结果仍然可追溯，局部重跑可控。

**不属于首版**：媒体编辑器、多轨声音编辑、自动配音/声音克隆、资产市场与云端同步。
